# 03. Нутриенты, нормы, анализ сбалансированности и рекомендации

[← к оглавлению](README.md)

## 1. Нутриентная база

### 1.1. Источники

| Приоритет | Источник | Формат загрузки | Что берём |
|---|---|---|---|
| 1 | Этикетка конкретного продукта (OCR/ввод) | — | КБЖУ, соль, сахара — для этого продукта |
| 2 | Таблицы химического состава российских пищевых продуктов (Скурихин, Тутельян; данные ФИЦ питания и биотехнологии) | Импорт подготовленного CSV | Локальные продукты: творог, кефир, ряженка, гречка, ржаной хлеб и т. п. |
| 3 | USDA FoodData Central (Foundation Foods, SR Legacy, FNDDS) | Ежеквартальный дамп CSV/JSON | 150+ нутриентов; основной источник витаминов, минералов, жирных кислот |
| 4 | CIQUAL (Франция), McCance & Widdowson (Великобритания) | CSV | Заполнение пробелов |
| — | Open Food Facts | API + локальный кэш | Магазинные продукты по штрихкоду (в основном КБЖУ и состав) |

### 1.2. Внутренняя модель
- **Продукт справочника** (`food_item`) — каноническая запись («Творог 5 %»), с названием на русском, синонимами, категорией, плотностью, съедобной частью (доля отходов: у банана — 0,64).
- **Значение нутриента** (`food_nutrient`): `food_item_id, nutrient_code, value_per_100g, source, source_ref, quality` где `quality` ∈ {`measured`, `calculated`, `imputed`, `label`}.
- **Список нутриентов** (минимум): энергия; белки; жиры (насыщенные, мононенасыщенные, полиненасыщенные, ω-3 (ALA, EPA+DHA), ω-6, трансжиры); холестерин; углеводы (сахара, добавленные сахара, крахмал); пищевые волокна; вода; натрий; калий; кальций; магний; фосфор; железо; цинк; медь; марганец; селен; йод; витамины A (RAE), D, E, K, C, B1, B2, B3 (NE), B5, B6, B7, B9 (DFE), B12; холин.
- **«Нет данных» ≠ 0.** Отсутствующее значение хранится как NULL.

### 1.3. Сопоставление источников (маппинг)
При импорте каждый продукт российских таблиц сопоставляется с продуктом USDA (полуавтоматически: текстовые эмбеддинги названий + сравнение КБЖУ, расхождение по энергии ≤ 15 %; затем ручная проверка списка ~500 ключевых продуктов на этапе разработки). Итоговое значение нутриента для `food_item` выбирается по правилу:

```
для каждого нутриента:
  если есть значение из источника с более высоким приоритетом → берём его
  иначе если есть сопоставленный продукт из источника ниже → берём с пометкой imputed
  иначе NULL
```

КБЖУ всегда берутся из наиболее приоритетного источника, микронутриенты — из наиболее полного, если в приоритетном их нет. Источник каждого значения доступен в интерфейсе («откуда эта цифра?»).

### 1.4. Обновление
Ежеквартальная задача `reference_import`: загрузка новых версий, пересчёт итоговых значений, отчёт об изменениях > 10 % по ключевым продуктам. Состав уже записанных приёмов пищи не меняется (снимок), если администратор не запустит пересчёт явно.

## 2. Расчёт состава блюд

### 2.1. Домашнее блюдо по рецепту
Входные данные рецепта: ингредиенты (продукт справочника + масса брутто или нетто + состояние «сырой»), способ приготовления (варка, жарка, тушение, запекание, без обработки), выход готового блюда (взвешенный или расчётный).

Алгоритм:
1. **Масса нетто** = брутто × съедобная часть (если указано брутто).
2. **Нутриенты сырых ингредиентов**: `N_raw[n] = Σ_ingr масса_нетто × value[n] / 100`.
3. **Потери при обработке** — коэффициенты сохранности по нутриенту и способу приготовления (таблицы USDA Nutrient Retention Factors; например, витамин C при варке овощей ≈ 0,5–0,7; минералы ≈ 0,9–1,0; белки, жиры, углеводы ≈ 1,0):
   `N_cooked[n] = Σ_ingr масса × value[n] / 100 × retention[n, группа_ингредиента, способ]`.
4. **Масло при жарке:** указывается количество в рецепте; по умолчанию поглощается доля, зависящая от продукта (панированные — до 50 % масла сковороды, без панировки — ~20 %); остальное «остаётся в сковороде» и не учитывается.
5. **Выход готового блюда:** взвешенный (если взвешивали) или `Σ масса_нетто × yield_factor(способ, категория)` (уварка супа ~0,9, жарка мяса ~0,7, варка крупы — рост массы ×2,5–3 за счёт воды, задаётся у ингредиента «крупа» через коэффициент).
6. **Состав на 100 г готового** = `N_cooked / выход × 100`.
7. **Полнота:** для каждого нутриента — доля массы ингредиентов, по которым значение известно. Если < 80 % — значение помечается «неполное».

Партия использует рецепт с фактическими изменениями (замены, пропуски ингредиентов) и фактическим выходом.

### 2.2. Магазинный продукт
КБЖУ — с этикетки (приоритет); микронутриенты — от сопоставленного продукта справочника (модель предлагает аналог по названию и составу; человек может поменять). Пометка «микронутриенты оценены по аналогу».

### 2.3. Блюдо вне дома
По аналогу из справочника или рецепту «как дома» + поправочный коэффициент на жирность для ресторанной еды (по умолчанию ×1,15 к жирам; настраивается).

## 3. Нормы потребления

### 3.1. Источники норм
- **Основной:** МР 2.3.1.0253-21 «Нормы физиологических потребностей в энергии и пищевых веществах для различных групп населения Российской Федерации» — по полу и возрастным группам, для детей, беременных и кормящих.
- **Верхние допустимые уровни** (UL) — по МР и EFSA/IOM для показателей, где их нет в МР.
- **Ограничения ВОЗ:** добавленные сахара < 10 % энергии (желательно < 5 %), соль < 5 г/сут, насыщенные жиры < 10 % энергии.
- Таблица норм хранится в БД (`nutrient_norm`: группа, нутриент, норма, UL, единица, источник) и может обновляться без изменения кода.

### 3.2. Индивидуальный расчёт
1. **Основной обмен** (BMR) — формула Миффлина — Сан Жеора:
   мужчины `10·вес + 6,25·рост − 5·возраст + 5`; женщины `… − 161`.
   Для детей — нормы энергии по возрастной группе МР.
2. **Суточная потребность** `TDEE = BMR × КФА` (коэффициент физической активности 1,2–1,9 по уровню активности; в v2 — из данных трекера).
3. **Цель:** снижение массы — дефицит 10–20 % (не ниже BMR × 1,1 и не быстрее 0,5–1 % массы в неделю); набор — профицит 10 %; поддержание — 0.
4. **Адаптация:** раз в 2 недели, при наличии ≥ 6 взвешиваний, фактическая TDEE оценивается по балансу: `TDEE_факт ≈ средняя_энергия_рациона − Δмассы_кг × 7700 / дней`; если расхождение с формулой > 10 % и устойчиво 4 недели — предлагается скорректировать норму (с объяснением). Это одновременно проверяет точность учёта.
5. **Макронутриенты:** белок — 0,8–1,2 г/кг (выше при снижении массы/тренировках, по МР для детей); жиры — 25–30 % энергии; углеводы — остаток (не менее 130 г для взрослых); клетчатка — 20–25 г (МР) / 14 г на 1000 ккал.
6. **Микронутриенты:** норма по группе МР; для беременных/кормящих — соответствующие надбавки.
7. Ручная корректировка любой нормы (например, по назначению врача) с пометкой «изменено вручную».

## 4. Анализ сбалансированности

### 4.1. Агрегаты
- **Дневное потребление** участника: `Σ позиций масса × N_100[n] / 100` (по снимку нутриентов позиции). Хранится в `daily_intake` (материализованный агрегат), пересчитывается при любом изменении записей дня.
- **Полнота дня:** оценка того, записано ли всё. День считается «неполным», если энергия < 60 % нормы и нет пометки «разгрузочный/болел», или пропущен основной слот, обычно присутствующий у участника. Неполные дни **исключаются** из недельных средних (и это показывается), чтобы не делать ложных выводов о дефицитах.
- **Покрытие данными:** для каждого нутриента — доля энергии дня, пришедшая из продуктов, где значение нутриента известно.

### 4.2. Оценка статуса нутриента (за 7 и 28 дней)
Среднесуточное по полным дням, в % от нормы:

| Статус | Правило | Цвет |
|---|---|---|
| Выраженный дефицит | < 50 % нормы | Красный |
| Дефицит | 50–80 % | Оранжевый |
| Норма | 80–150 % (для энергии 90–110 %) | Зелёный |
| Избыток | > 150 % нормы (для ограничиваемых — соль, сахара, насыщенные жиры — > 100 % лимита) | Оранжевый |
| Выше UL | > верхнего допустимого уровня | Красный |
| Недостаточно данных | Покрытие < 70 % или полных дней < 4 из 7 | Серый |

Энергия и макронутриенты оцениваются также по дням (дневной отчёт), микронутриенты — **только** за период ≥ 7 дней.

### 4.3. Источники нутриента
Для каждого нутриента — список блюд, давших наибольший вклад за период (вклад = Σ массы × содержание). Используется в отчётах («80 % соли — колбаса, хлеб, сыр») и в рекомендациях.

### 4.4. Показатели качества рациона
| Показатель | Расчёт |
|---|---|
| Разнообразие | Число разных продуктов-ингредиентов за неделю (по рецептам и простым продуктам) |
| Овощи и фрукты | г/сут (цель ≥ 400 г по ВОЗ, без картофеля) |
| Ультрапереработанные продукты | Доля энергии из продуктов категории NOVA 4 (классификация — из Open Food Facts / по категории блюда) |
| Регулярность | Разброс времени приёмов пищи, поздние приёмы (< 2 ч до сна, если указано время сна) |
| Белок по приёмам | Распределение белка по приёмам пищи |

### 4.5. Семейный анализ
Сводка по всем участникам: какие дефициты общие (вероятная причина — общие блюда семьи, значит, и решение — в общем плане), какие индивидуальные.

## 5. Рекомендации

### 5.1. Принципы
- **Конкретные и выполнимые:** привязаны к блюдам, которые семья уже ест или легко может готовить.
- **Мало:** 1–3 рекомендации в неделю на участника, по приоритету.
- **Проверяемые:** рекомендация, принятая пользователем, превращается в изменение плана, и через 2–4 недели система показывает, изменился ли показатель.
- **Безопасные:** не предлагать продукты с аллергенами/запретами участника; не советовать добавки и лекарства (только «обсудите с врачом» для выраженных устойчивых дефицитов).

### 5.2. Алгоритм
1. **Список проблем:** все нутриенты со статусом дефицит/избыток за 28 дней (или 14 дней при наличии меньшего объёма данных) с достаточным покрытием данных.
2. **Приоритет проблемы:** `priority = тяжесть × важность × устойчивость`, где тяжесть — отклонение от нормы (|1 − факт/норма|), важность — экспертный вес нутриента (выше для белка, клетчатки, железа у женщин, кальция и витамина D у детей, соли, добавленного сахара), устойчивость — доля недель периода с этой проблемой.
3. **Поиск действий** для каждой проблемы из топ-3. Типы действий:
   - **замена** блюда A → B в том же слоте и категории (макароны → гречка);
   - **добавление** небольшой позиции (горсть орехов, овощной салат к ужину);
   - **изменение рецепта** (часть майонеза → сметана; меньше соли);
   - **изменение частоты** (рыба 1 → 2 раза в неделю).
   Кандидаты B берутся сначала из каталога семьи (уже едят!), затем из библиотеки популярных блюд.
4. **Оценка действия:** моделируется недельный рацион с применённым действием (по фактической частоте блюда A у участника) и считается:
   `польза = Σ_проблемы улучшение_покрытия × приоритет − штраф_за_новые_проблемы − штраф_за_изменение_энергии (если > 5 %) − штраф_новизны (блюдо не из каталога) − штраф_непопулярности (блюдо B участник ел редко и много раз пропускал в плане)`.
5. **Выбор:** 1–3 лучших действия с разными проблемами.
6. **Формулировка:** LLM получает структуру (проблема, цифры, действие, ожидаемый эффект) и пишет короткий понятный текст. Цифры в тексте подставляются из структуры, а не генерируются моделью (проверка: все числа в тексте должны присутствовать в структуре, иначе — шаблонная формулировка).

Пример результата:
> **Мало магния (62 % нормы).** Вы едите макароны 4 раза в неделю на ужин. Если 2 раза заменить их гречкой (вы её уже готовите), магний вырастет до ~85 % нормы, калорийность не изменится. [Добавить в план]

### 5.3. Обратная связь по рекомендациям
Действия пользователя: «Добавить в план», «Не подходит» (с причиной: не любим / дорого / долго готовить) → причины учитываются как штрафы в будущих рекомендациях и в планировщике.

## 6. Отчёты

| Отчёт | Содержание | Когда |
|---|---|---|
| Дневной | Энергия и БЖУ: факт/норма/план; по приёмам пищи; вода; «осталось на сегодня» | Всегда на главном экране |
| Недельный | Средние КБЖУ, динамика, «светофор» микронутриентов, качество рациона, соблюдение плана, 1–3 рекомендации | Воскресенье вечером (push) |
| Месячный | Устойчивые проблемы, источники нутриентов, динамика веса и фактической TDEE, прогресс по рекомендациям | 1-го числа |
| Семейный | Сводка по участникам, общие проблемы, самые частые блюда | В веб-кабинете и недельном отчёте администратора |
| Качество распознавания | См. [02-recognition.md](02-recognition.md), раздел 8.7 | В веб-кабинете |

Все отчёты доступны в экспорте (PDF/CSV), например, для показа врачу-диетологу.

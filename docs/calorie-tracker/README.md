## 1. Назначение

Система позволяет членам одной семьи фиксировать всё съеденное за несколько секунд — сфотографировав тарелку или наговорив фразу — и на основе накопленных данных:

1. считать калории, белки, жиры, углеводы (КБЖУ) и микронутриенты;
2. оценивать сбалансированность рациона каждого члена семьи и семьи в целом;
3. давать конкретные рекомендации на основе блюд, которые семья реально ест;
4. составлять план питания на неделю и список покупок;
5. контролировать соблюдение плана.

## 2. Главный принцип: «замкнутый мир» семьи

Универсальные приложения решают задачу «что это за еда из всех существующих в мире?» и поэтому ошибаются. У одной семьи рацион ограничен и повторяется: 50–150 блюд, одна и та же посуда, одни и те же рецепты, магазины и привычки. Система **выучивает этот замкнутый набор** и решает гораздо более простую задачу: *«какое из наших блюд это и сколько его?»*

Отсюда архитектурные решения, проходящие через весь документ:

| Принцип | Что это значит на практике |
|---|---|
| Каталог — источник истины | Итоговый ответ распознавания всегда — ссылка на блюдо из семейного каталога (или явное создание нового блюда). Свободный текст модели никогда не сохраняется как результат. |
| Модель понимает, каталог уточняет | Мультимодальная модель (LLM) отвечает за «понимание» фото и речи, а выбор конкретного блюда, порции и нутриентов делается по данным семьи. |
| Каждая правка — обучающий пример | Любое подтверждение или исправление сохраняется и улучшает последующее распознавание: эталонные фото, синонимы, типичные порции, контекстные вероятности. |
| Контекст важнее пикселей | Кто ест, когда, что сегодня готовили (партии), что в плане — всё это учитывается при выборе блюда наравне с изображением. |
| Числа считает код, тексты пишет модель | Калории, нормы, дефициты, оптимизация плана — детерминированные алгоритмы. LLM формулирует пояснения и разбирает свободную речь. |
| Один сервер — много устройств | Все данные семьи живут на одном сервере; приложения — клиенты с офлайн-кэшем и синхронизацией. |

## 3. Измеримые цели

| № | Цель | Целевое значение (после 4 недель обучения) |
|---|---|---|
| Ц1 | Точность определения блюда top-1 для блюд из каталога | ≥ 95 % |
| Ц2 | Точность top-3 (выбор одним тапом) | ≥ 99 % |
| Ц3 | Ошибка массы порции (MAPE) | ≤ 15 % по фото; ≤ 10 % по голосу с указанием количества |
| Ц4 | Время записи приёма пищи (от открытия до сохранения) | медиана ≤ 10 с |
| Ц5 | Доля записей без ручной правки | ≥ 85 % |
| Ц6 | Ошибка суточной калорийности против контрольного взвешивания | ≤ 10 % |
| Ц7 | Задержка распознавания фото на сервере | p50 ≤ 3 с, p90 ≤ 5 с |
| Ц8 | Время доставки записи на другие устройства семьи (при наличии сети) | ≤ 5 с |

Методика измерения — в [07-stages-acceptance.md](07-stages-acceptance.md).

## 4. Роли

| Роль | Описание | Права |
|---|---|---|
| Администратор семьи | Разворачивает сервер, создаёт семью, подключает устройства | Всё, включая управление участниками, устройствами, бюджетом AI, резервными копиями |
| Участник (взрослый) | Член семьи со своим устройством | Свои записи, записи за детей, общий каталог (добавление и правка), свои цели и планы, семейный план |
| Ребёнок / участник без устройства | Профиль без входа | Записи ведёт любой взрослый от его имени |
| Участник с ограниченным просмотром (опционально) | Например, подросток | Свои записи; не видит веса и отчёты других участников |

**Видимость данных внутри семьи** (настраивается администратором): по умолчанию все взрослые видят записи о еде друг друга (это нужно для общих приёмов пищи и плана), но **вес, цели и персональные отчёты** видит только сам участник и администратор, если участник не разрешил иначе.

## 5. Глоссарий

| Термин | Определение |
|---|---|
| Каталог | Набор блюд и продуктов, которые ест семья, с рецептами, порциями, эталонными фото и синонимами |
| Блюдо (Dish) | Элемент каталога: домашнее блюдо по рецепту, магазинный продукт, блюдо вне дома или простой продукт |
| Вариант блюда | Блюда, похожие визуально, но разные по составу («котлеты куриные» / «котлеты говяжьи»); связаны в группу |
| Партия (Batch) | Конкретная порция приготовленного блюда (кастрюля супа, противень запеканки) с фактическим составом и остатком |
| Приём пищи (MealEntry) | Факт еды: кто, когда, исходные фото/аудио/текст и список позиций |
| Позиция (MealItem) | Одно блюдо в приёме пищи с массой и источником оценки |
| Задача распознавания (RecognitionJob) | Серверная задача обработки фото/голоса/текста, возвращающая гипотезы |
| Гипотеза | Предложение системы: блюдо + масса + уверенность |
| Эталонное фото | Подтверждённый пользователем фрагмент фото блюда с вычисленным эмбеддингом |
| Эмбеддинг | Числовой вектор, описывающий изображение или текст; близкие векторы — похожее содержимое |
| Контекстный приор | Вероятность блюда исходя из кто/когда/что обычно ест, без учёта фото |
| Слот | Тип приёма пищи: завтрак, второй завтрак, обед, полдник, ужин, перекус |
| Устройство | Экземпляр приложения, подключённый к серверу и привязанный к участнику |
| Нутриент | Энергия, белки, жиры, углеводы, витамины, минералы и т. п. |
| КБЖУ | Калории, белки, жиры, углеводы |

## 6. Вне рамок первой версии

- Публичная регистрация, монетизация, социальные функции.
- Медицинская диагностика и лечебные диеты: система не является медицинским изделием, рекомендации информационные.
- Интеграция с фитнес-трекерами, умными весами, магазинами (кандидаты на v2, см. [07-stages-acceptance.md](07-stages-acceptance.md)).

## 7. Открытые вопросы к семье

1. Состав семьи, возраст детей, особые диеты, аллергии.
2. Устройства: iOS, Android, планшет на кухне?
3. Допустимо ли отправлять фото еды во внешние AI-сервисы, или нужен полностью локальный вариант (дороже по железу и менее точно)?
4. Где размещать сервер: арендованный VPS (рекомендуется) или домашний компьютер / NAS?
5. Готова ли семья первые 2–4 недели тратить больше времени на подтверждение записей?
6. Есть ли кухонные весы?
7. Где часто едят вне дома (столовая, кафе)?
8. Нужен ли учёт бюджета продуктов?

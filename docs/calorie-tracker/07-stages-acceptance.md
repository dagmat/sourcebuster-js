## 2. Методика проверки точности распознавания

### 2.1. Наборы данных
- **Золотой набор** — подтверждённые записи с правильным ответом (раздел 8.8 в [02-recognition.md](02-recognition.md)); для приёмки используется выборка за последние 7 дней перед приёмкой, не участвовавшая в обучении весов.
- **Контрольные взвешивания** — записи с массой, измеренной на весах (не менее 30 позиций за период приёмки), для оценки MAPE массы.
- **Контрольные дни** — не менее 3 дней на участника, когда вся еда взвешивается, для цели Ц6 (ошибка суточной энергии).

### 2.2. Метрики
| Метрика | Формула |
|---|---|
| top-1 | доля позиций, где блюдо с рангом 1 совпало с итоговым |
| top-3 | доля позиций, где итоговое блюдо в первых трёх |
| MAPE массы | среднее abs(оценка − факт) / факт по контрольным взвешиваниям (с исключением позиций < 20 г) |
| Ошибка энергии дня | abs(Σ энергии по оценке − Σ по взвешиванию) / Σ по взвешиванию для контрольных дней |
| Доля без правки | записи, сохранённые без изменения позиций / все записи |
| Время записи | от открытия приложения (или нажатия виджета) до сохранения, медиана |
| Задержка распознавания | от завершения загрузки до `recognition.completed`, p50/p90 |

Блюда вне каталога (новые) учитываются отдельно: метрика — доля корректно определённых как «новое» (не выданных уверенно за каталоговое).

## 3. Критерии приёмки по этапам

### Этап 0
- top-3 ≥ 90 % на 20 блюдах при 5 эталонах; стоимость распознавания одного фото ≤ 0,02 $; задержка p50 ≤ 4 с.
- Если не достигнуто — пересмотр подхода до начала разработки этапа 1.

### Этап 1 (сервер)
- Установка «с нуля» по инструкции ≤ 30 минут.
- Подключение устройства по QR; отзыв устройства приводит к 401 в течение ≤ 15 минут (срок access-токена).
- Синхронизация: запись, созданная на устройстве A, появляется на B ≤ 5 с; запись, созданная офлайн, доставляется после восстановления сети без дублей (тест с обрывом соединения во время отправки).
- Конфликтные тесты: одновременное изменение одной записи с двух устройств — без потерь (версия в истории); одновременный расход партии — корректный остаток.
- Тесты матрицы прав: 100 % сценариев таблицы 4.4 из [01-server.md](01-server.md).
- Отказ внешнего AI: распознавание возвращает `pick_from_top3` по локальному пути, без ошибки пользователю.
- Лимит стоимости AI работает (уведомление на 80 %, переключение на 100 %).
- OpenAPI-спецификация соответствует реализации (контрактные тесты).

### Этап 2 (приложение)
- Все сценарии раздела 3 [05-clients.md](05-clients.md) проходят на iOS и Android.
- Время от касания «Фото» до готовой камеры ≤ 1,5 с.
- Офлайн: 10 записей без сети → все доставлены и распознаны после подключения.

### Этап 3 (главный критерий проекта)
После 4 недель реального использования семьёй, на данных последней недели:
- top-1 ≥ 95 %, top-3 ≥ 99 % для блюд каталога;
- MAPE массы ≤ 15 % (фото), ≤ 10 % (голос с количеством);
- доля записей без правки ≥ 85 %;
- медиана времени записи ≤ 10 с;
- ошибка энергии контрольных дней ≤ 10 %;
- доля ошибок среди автосохранённых позиций ≤ 3 %.

### Этап 4
- Расчёт состава 20 эталонных рецептов совпадает с ручным расчётом диетолога/по таблицам с расхождением ≤ 5 % по КБЖУ.
- Нормы для каждой группы МР рассчитываются корректно (табличные тесты).
- Рекомендации не нарушают аллергии/запреты (автотест на 100 сгенерированных профилей); числа в тексте рекомендаций совпадают с рассчитанными.

### Этап 5
- План строится ≤ 30 с; соблюдены все жёсткие ограничения (автотесты на наборе сценариев, включая несовместимые ограничения с объяснением ослабления).
- Отклонение недельного плана от норм по энергии ≤ 5 %, по белку ≥ нижней границы.
- Статусы соблюдения корректны на размеченном наборе из 50 приёмов пищи (≥ 90 % совпадения с ручной разметкой).

### Этап 6
- Восстановление из резервной копии на чистом сервере ≤ 2 ч по инструкции (проведено фактически).
- Нет критических и высоких уязвимостей по результатам сканирования.

## 4. Возможное развитие (v2+)
- Apple Health / Google Health Connect: вес, активность, фактический расход энергии → нормы точнее.
- Bluetooth-весы (кухонные и напольные) — автоматическая точная масса порций и партий.
- Распознавание на устройстве (on-device) — приватность и офлайн.
- Telegram-бот как дополнительный канал записи («отправь фото в чат»).
- Анализы крови (ферритин, витамин D) для персонализации — по согласованию с врачом.
- Учёт цен, оптимизация плана по бюджету, интеграция со службами доставки продуктов.
- Обслуживание нескольких семей (родственников) на одном сервере — архитектура это уже допускает (`family_id`).

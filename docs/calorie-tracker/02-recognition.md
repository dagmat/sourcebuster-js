# 02. Распознавание съеденного: логика работы

[← к оглавлению](README.md)

Этот раздел — ядро системы. Описано, **как именно** фото, голос или текст превращаются в запись «кто, что, сколько», и **как система учится** на данных семьи.

## 1. Сквозной конвейер

```
 Вход: фото(а) / аудио / текст + контекст (кто, когда, устройство)
   │
   ▼
 [Э0] Предобработка ─── фото: проверка качества, эмбеддинг всего кадра
   │                    аудио: распознавание речи (STT) с подсказками словаря
   ▼
 [Э1] Генерация кандидатов из каталога (≈ 20–30 блюд)
   │    ├─ визуальный поиск по эталонным фото
   │    ├─ контекстный приор (кто/когда/что обычно)
   │    ├─ открытые партии (что сейчас приготовлено)
   │    ├─ план питания на этот слот
   │    └─ текстовый поиск (для голоса/текста)
   ▼
 [Э2] Извлечение позиций мультимодальной моделью
   │    вход: фото/текст + список кандидатов + посуда + меры
   │    выход: JSON — позиции, выбранное блюдо (ID кандидата или «новое»),
   │           количество/объём, области на фото
   ▼
 [Э3] Уточнение по каждой позиции
   │    ├─ повторный визуальный поиск по вырезанному фрагменту
   │    ├─ итоговый скоринг кандидатов (объединение всех сигналов)
   │    └─ выбор варианта блюда и партии
   ▼
 [Э4] Оценка массы порции (несколько методов + байесовское объединение)
   ▼
 [Э5] Калибровка уверенности и решение: автосохранение / выбор из 3 / вопрос
   ▼
 [Э6] Ответ клиенту (WebSocket), подтверждение пользователем
   ▼
 [Э7] Обратная связь → обучение (эталоны, синонимы, порции, приоры, веса)
```

Каждый этап записывает свои результаты в `recognition_job.stages` (JSON), чтобы любую ошибку можно было разобрать постфактум.

## 2. Семейный каталог: что нужно для распознавания

Распознавание опирается на следующие данные каталога (полная модель — [06-data-model.md](06-data-model.md)):

| Данные | Пример | Как используется |
|---|---|---|
| Название и синонимы | «Котлеты куриные»: «котлеты», «котлетки», «мамины котлеты», «куриные котлеты» | Сопоставление речи и текста; подсказки STT |
| Группа вариантов | {Котлеты куриные, Котлеты говяжьи, Тефтели} | Если модель уверена в группе, но не в варианте — решают контекст и партии |
| Категория | Второе / гарнир / суп / салат / напиток / выпечка / молочное / фрукт / соус | Ограничения при оценке массы, правила плана |
| Единица счёта | 1 котлета = 85 г (σ = 10 г) | Оценка массы по количеству штук |
| Плотность | Пюре 1,05 г/мл; суп 1,0; салат с майонезом 0,75 | Перевод объёма в массу |
| Эталонные фото | 5–200 фрагментов с эмбеддингами | Визуальный поиск |
| Визуальное описание | «светло-коричневые овальные, в панировке» | Подсказка модели для различения похожих блюд |
| Типичные порции | Папа: медиана 255 г; дочь: 85 г | Приор для массы |
| Контекстная статистика | Чаще всего: ужин, будни | Контекстный приор |

**Типы блюд и их особенности:**

| Тип | Источник состава | Особенность распознавания |
|---|---|---|
| Домашнее по рецепту | Расчёт из рецепта | Визуально изменчиво; важны партии |
| Магазинный продукт | Этикетка / Open Food Facts | Распознаётся по упаковке/штрихкоду; масса — по упаковке или доле |
| Блюдо вне дома | Оценка по аналогу / меню заведения | Привязка к месту (опционально по выбору пользователя «где») |
| Простой продукт | Справочник | Яблоко, хлеб, сыр — счёт штук/ломтиков |
| Составное «стандартное» | Набор других блюд | «Мой обычный завтрак» = овсянка + кофе с молоком |

## 3. Этап Э0: предобработка

### 3.1. Фото
1. **Проверка качества** (на сервере, < 50 мс): размытие (дисперсия лапласиана < порога), экспозиция (слишком тёмное/пересвеченное), размер. При провале — ответ `ask` с вопросом «Фото нечёткое, переснять?» и кнопкой «Всё равно распознать».
2. **Эмбеддинг всего кадра** — для визуального поиска на Э1.
3. **Детекция посуды** (выполняется моделью на Э2, но может ускоряться: если в кадре распознаётся эталонная тарелка из каталога посуды по эмбеддингу — это сразу передаётся модели как подсказка).
4. **Штрихкод** — если в кадре читается штрихкод (библиотека ZXing на клиенте или сервере), задача переключается в режим «продукт по штрихкоду» (раздел 5.4).

### 3.2. Аудио
1. STT с **подсказками словаря**: в модель распознавания речи передаётся строка-подсказка (initial prompt / hotwords) из ~200 самых частых названий и синонимов каталога, имён членов семьи и семейных мер («кружка», «пиалка»). Это критично: «сырники» не превратятся в «сырки», а «Лиза» — в «лиса».
2. Нормализация текста: числительные словами → числа («полторы» → 1,5; «пару» → 2), удаление слов-паразитов.
3. Сохранение текста и сегментов с временными метками.

### 3.3. Определение контекста
| Поле | Как определяется |
|---|---|
| Участник(и) | Из запроса (по умолчанию — владелец устройства; на общем устройстве — «семья») или из речи («Маша съела…») |
| Время приёма | Из речи («вчера вечером») → иначе время съёмки (EXIF) → иначе время запроса |
| Слот | По времени и привычкам участника: распределение времени слотов вычисляется из истории (например, обед у папы 12:30–14:30); первые 2 недели — стандартные окна |
| Открытые партии | Все незакрытые партии семьи с остатком > 0 |
| План | Запланированные блюда для участника на этот слот и этот день |

## 4. Этап Э1: генерация кандидатов

Цель — сузить каталог до 20–30 вероятных блюд, чтобы модель выбирала из короткого списка, а не из всего мира. Кандидаты собираются из нескольких источников, затем объединяются.

### 4.1. Визуальный поиск (для фото)
1. Поиск 100 ближайших эталонных фрагментов к эмбеддингу кадра (pgvector, косинусная близость).
2. Агрегация по блюдам: для каждого блюда `vis(d) = 0.6 · max_sim + 0.4 · mean(top3_sim)` (усреднение по трём лучшим устойчивее к единичному «случайному» совпадению).
3. Берутся топ-15 блюд по `vis`.

На раннем этапе эталонов мало, поэтому кадр с несколькими блюдами похож «на всё понемногу». Это нормально: окончательный визуальный скоринг делается на Э3 по фрагментам.

### 4.2. Контекстный приор
Вероятность, что участник `m` ест блюдо `d` в слот `s` в день недели `w`, оценивается по истории подтверждённых записей с затуханием по времени (период полураспада 30 дней — рацион меняется сезонно):

```
count(d | m, s) = Σ по записям  exp(−возраст_дней · ln2 / 30)
P_ctx(d | m, s) = (count(d|m,s) + α · P(d | семья, s) + β · P(d | семья)) / нормировка
```
Сглаживание через семейные частоты нужно, чтобы новое для участника, но обычное для семьи блюдо не получало нулевую вероятность. Коэффициенты α, β — гиперпараметры (стартовые 2 и 0,5).
Берутся топ-10 по приору.

### 4.3. Открытые партии
Все блюда открытых партий добавляются в кандидаты безусловно. Признак `batch_fresh(d)` = 1, если партия приготовлена сегодня или вчера и остаток > 10 %.

### 4.4. План
Все блюда из плана на этот слот добавляются в кандидаты. Признак `planned(d) = 1`.

### 4.5. Текстовый поиск (голос/текст)
Для каждого упомянутого в речи фрагмента (результат разбора на Э2, см. 5.3) — поиск по каталогу:
- точное совпадение с названием/синонимом после лемматизации → `text = 1.0`;
- триграммное сходство (опечатки, неточности STT) → `text = sim_trgm`;
- семантическое сходство текстовых эмбеддингов («куриные биточки» ↔ «котлеты куриные») → `text = sim_emb · 0.9`.

### 4.6. Объединение
Итоговый список — объединение всех источников, дедуплицированный; плюс **все варианты из групп** попавших блюд (чтобы модель видела «котлеты куриные» и «котлеты говяжьи» рядом). Ограничение — 30 блюд. Для каждого кандидата модели передаются: ID, название, категория, короткое визуальное описание, единица счёта.

## 5. Этап Э2: извлечение позиций моделью

### 5.1. Фото: запрос к мультимодальной модели

**Входные данные:**
- изображение (или два — режим «до/после»);
- список кандидатов (раздел 4.6);
- каталог посуды семьи (название, диаметр/объём, краткое описание внешнего вида);
- если пользователь добавил голосовую/текстовую подпись — её текст.

**Инструкция модели (суть промпта):**
1. Найди на фото все отдельные виды еды и напитков.
2. Для каждого выбери блюдо из списка кандидатов по ID. Если подходящего нет — `new` с кратким названием и описанием.
3. Если не уверен между несколькими кандидатами — перечисли до 3 с вероятностями.
4. Определи посуду (ID из каталога посуды или `unknown`).
5. Оцени количество: штуки для счётных блюд; долю заполнения посуды (0–1) для супов, гарниров, напитков; массу в граммах как независимую оценку.
6. Укажи область на фото (нормализованный прямоугольник).
7. Отметь видимые модификаторы (сметана сверху, соус, масло, зелень) как отдельные позиции, если их масса значима (> 10 г).
8. Не придумывай: если еда не видна или фото не о еде — верни пустой список и причину.

**Схема ответа (валидируется сервером):**
```json
{
  "image_ok": true,
  "reason_if_not_ok": null,
  "items": [
    {
      "candidates": [
        {"dish_id": "d_kotlety_kurinye", "p": 0.85},
        {"dish_id": "d_kotlety_govyazhi", "p": 0.15}
      ],
      "new_dish": null,
      "region": {"x": 0.12, "y": 0.30, "w": 0.35, "h": 0.28},
      "dishware_id": "dw_plate_white_24",
      "count": 2,
      "fill_fraction": null,
      "grams_estimate": 180,
      "notes": "в панировке, золотистые"
    }
  ]
}
```

### 5.2. Режим «до и после»
Модель получает два фото и возвращает для каждой позиции долю съеденного `eaten_fraction` (или количество оставшихся штук). Масса съеденного = масса «до» × `eaten_fraction`. Если позиции на втором фото нет — съедено всё.

### 5.3. Голос/текст: разбор фразы
Модель получает текст фразы, список кандидатов (с синонимами), список участников с именами-алиасами («Маша», «дочка», «мелкая» → `m_masha`), словарь мер и текущую дату/время. Возвращает:

```json
{
  "meals": [
    {
      "member_refs": ["m_papa"],
      "time_ref": {"type": "relative", "value": "today_lunch"},
      "items": [
        {"text": "тарелка борща", "candidates": [{"dish_id": "d_borsch", "p": 0.95}],
         "quantity": {"amount": 1, "unit": "plate"}, "modifiers": ["со сметаной"]},
        {"text": "сметана", "candidates": [{"dish_id": "d_smetana_15", "p": 0.8}],
         "quantity": {"amount": null, "unit": null}, "implicit": true},
        {"text": "кусок чёрного хлеба", "candidates": [{"dish_id": "d_hleb_borodinsky", "p": 0.9}],
         "quantity": {"amount": 1, "unit": "slice"}}
      ]
    }
  ],
  "corrections": []
}
```

Особые случаи разбора:
| Фраза | Логика |
|---|---|
| «Как вчера на завтрак» | Ссылка на прошлый приём → копия позиций с теми же массами |
| «Мой обычный завтрак» | Ссылка на составное «стандартное» блюдо |
| «Нет, не две, а три котлеты» | `corrections`: изменение количества в последней записи (в течение 30 мин) |
| «Мы с дочкой съели пиццу» | Один приём, несколько участников → распределение (раздел 6.5) |
| «Полтарелки супа» | `amount = 0.5, unit = plate` |
| «Немного», «чуть-чуть» | Количество не указано явно → приор порции × 0,5 с пониженной уверенностью массы |
| «Съел 200 грамм творога» | Явная масса → источник `explicit`, уверенность массы 0,98 |
| «Выпил кофе» | Напиток: стандартная кружка участника, состав — «кофе с молоком без сахара», если так в 80 %+ случаев у этого участника |

### 5.4. Режим «этикетка / штрихкод»
1. Штрихкод найден → поиск в каталоге семьи (уже покупали?) → в локальном кэше Open Food Facts → в API Open Food Facts.
2. Найден → блюдо-продукт создаётся или используется; масса = вес упаковки или доля, указанная пользователем («съел половину»).
3. Не найден → модель читает с фото этикетки название, массу нетто, КБЖУ на 100 г и состав (OCR) → создаётся продукт с пометкой «данные с этикетки» и предложением сфотографировать заднюю сторону, если КБЖУ не видны.

## 6. Этап Э3–Э4: выбор блюда и оценка массы

### 6.1. Повторный визуальный поиск по фрагментам
Для каждой позиции из Э2 вырезается фрагмент по `region` (с полем 10 %), считается эмбеддинг, выполняется поиск ближайших эталонов **только среди кандидатов** позиции и их группы вариантов. Получаем `vis_item(d)`.

### 6.2. Итоговый скоринг блюда
Для каждой позиции и каждого кандидата `d` строится вектор признаков:

| Признак | Описание |
|---|---|
| `p_llm` | Вероятность от модели (0, если кандидата не назвала) |
| `vis_item` | Визуальное сходство фрагмента с эталонами блюда |
| `n_refs` | log(1 + число эталонов блюда) — доверие к визуальному сходству растёт с числом эталонов |
| `log_prior` | log P_ctx(d \| m, s) |
| `batch_fresh` | Есть свежая открытая партия |
| `planned` | Блюдо в плане на этот слот |
| `text` | Текстовое совпадение (голос/подпись) |
| `recent_same` | Это блюдо этот участник уже записывал сегодня (повторы в течение дня реже) |

Скор: `score(d) = σ(w · features + b)`; вероятности по кандидатам позиции — softmax по `w · features`.

- **Стартовые веса** (холодный старт) задаются вручную: модель — главный сигнал, визуальное сходство — второй, приор/партии/план — уточняющие (например, `w_llm = 3.0, w_vis = 2.0 · min(1, n_refs/10), w_prior = 0.5, w_batch = 1.0, w_plan = 0.5, w_text = 3.0`).
- **Обучение весов:** еженедельно (и ночью после ≥ 200 новых подтверждений) веса переобучаются логистической регрессией на накопленных примерах `recognition_feedback` (правильное блюдо = 1, остальные кандидаты = 0). Новые веса принимаются, только если на отложенной выборке (последние 20 % по времени) top-1 точность не хуже текущей.

**Правило варианта.** Если модель уверена в группе (сумма вероятностей вариантов группы ≥ 0,9), но внутри группы распределение неопределённое, вариант выбирается по партии (если есть открытая партия одного из вариантов — он) и по приору. Например, котлеты на фото, а вчера жарили куриные → «котлеты куриные» с высокой уверенностью.

**Правило нового блюда.** Если модель вернула `new_dish` и лучший кандидат имеет `score < 0.3` — позиция помечается как новое блюдо; пользователю предлагается создать блюдо (раздел 8.4) или выбрать из похожих.

### 6.3. Выбор партии
Если выбранное блюдо имеет открытые партии: берётся самая свежая с остатком ≥ оценки массы; если несколько и неясно — самая старая с ненулевым остатком (FIFO, как реально едят). Связь с партией даёт точный состав (из фактического рецепта этой партии) и уточнение массы (раздел 6.4, метод М1).

### 6.4. Оценка массы: методы
Для каждой позиции вычисляется несколько независимых оценок, каждая со своей погрешностью (σ, в долях от значения):

| Метод | Когда применим | Оценка | Погрешность σ |
|---|---|---|---|
| М0. Явная масса | Пользователь сказал/ввёл граммы; кухонные весы | Как указано | 0,02 |
| М1. Взвешивание партии | Партия взвешивалась до и после | Разница масс кастрюли | 0,03 |
| М2. Счёт штук | Счётное блюдо (котлеты, сырники, ломтики хлеба) и известно `count` | count × масса_единицы (своя для блюда, уточняется обучением) | σ_единицы / √count + 0,05 |
| М3. Объём по посуде | Известна посуда и доля заполнения | fill × объём_посуды × плотность × k_калибровки | 0,20 (снижается калибровкой до ~0,12) |
| М4. Оценка модели | Всегда | `grams_estimate` × k_модели(категория) | 0,35 (снижается калибровкой) |
| М5. Приор порции | Всегда | Медиана порций участника для блюда (или семейная; или справочная) | Фактический разброс порций участника (CV), не менее 0,15 |
| М6. Мера из речи | «Тарелка», «половник», «ложка» | Количество × размер меры (семейный словарь, своя для блюда, если задана) | 0,15 |

**Объединение оценок** — взвешенное среднее в логарифмической шкале (ошибки массы мультипликативные), веса обратно пропорциональны дисперсиям:

```
ln_mass = Σ_i (ln m_i / σ_i²) / Σ_i (1 / σ_i²)
σ_итог  = 1 / sqrt(Σ_i 1/σ_i²)
масса   = exp(ln_mass)
```

Если присутствует М0 или М1 — они фактически доминируют, остальные почти не влияют. Если есть только М4 и М5 — результат тянется к привычной порции участника, что на практике снижает ошибку для повторяющихся приёмов пищи.

**Проверка разумности:** масса ограничивается диапазоном [0,2; 3] × приор порции; при выходе за диапазон (например, модель насчитала 900 г салата) масса обрезается, а уверенность массы снижается до ≤ 0,5 → пользователь увидит предложение уточнить.

**Уверенность массы:** `conf_mass = exp(−σ_итог / 0.25)`; например, σ = 0,05 → 0,82; σ = 0,15 → 0,55.

> Примечание: для М2 `conf_mass` дополнительно умножается на уверенность модели в количестве штук; если две котлеты частично перекрыты — модель может вернуть `count` с пометкой неуверенности.

### 6.5. Распределение общего приёма пищи
Случай: «мы с дочкой съели пиццу» / фото общей сковородки / запись с общего планшета «вся семья».

1. Определяется общая масса (по фото, партии или из речи: «целую пиццу»).
2. Доли участников по умолчанию — пропорционально их историческим порциям этого блюда; если истории нет — пропорционально суточной норме энергии (взрослый мужчина ~ 2 500 ккал, ребёнок 7 лет ~ 1 600 ккал).
3. Пользователь видит ползунки долей и может поправить; исправленные доли запоминаются как предпочтение для этого блюда и состава участников.
4. Создаётся один приём пищи с несколькими участниками; позиции дублируются по участникам с соответствующей массой; связь сохраняется (`shared_group_id`) — правка общей массы перераспределяет доли.

### 6.6. Модификаторы и скрытые ингредиенты
Масло для жарки, майонез в салате, сахар в чае не видны на фото, но дают много калорий.
- Для домашних блюд они уже в рецепте.
- Для напитков и простых продуктов — **привычки участника**: если в 80 %+ подтверждённых случаев кофе у мамы «с молоком 2,5 %, без сахара», это применяется по умолчанию и показывается в карточке («кофе с молоком, без сахара — изменить»).
- Голосовая подпись к фото («в салате майонез») — модель добавляет модификатор отдельной позицией.

## 7. Этап Э5: уверенность и решение

### 7.1. Расчёт
Для позиции: `conf_item = conf_dish^a · conf_mass^b`, где `conf_dish` — откалиброванная вероятность top-1 кандидата, `a = 1`, `b = 0.5` (ошибка в блюде хуже ошибки в массе).
Для приёма пищи — минимум по позициям, взвешенный по калорийности (ошибка в масле на 10 ккал не должна блокировать автосохранение).

### 7.2. Калибровка
Сырые вероятности моделей обычно переоценены. Еженедельно строится **изотоническая регрессия** «сырая уверенность → фактическая доля правильных» по истории подтверждений. Пока данных < 300 примеров — используется консервативная функция `calibrated = raw^1.5`.

### 7.3. Решение

| Условие | Решение | Что видит пользователь |
|---|---|---|
| Все позиции: `conf_dish ≥ T_auto` (старт 0,92) и `conf_mass ≥ 0,5`; нет новых блюд | `auto_save` | Запись сохранена; уведомление-карточка «Обед: котлеты ×2, пюре — 520 ккал» с кнопкой «Исправить» (активна всегда; заметная плашка — 30 с) |
| Есть позиция с `T_pick ≤ conf_dish < T_auto` (старт 0,6) | `pick_from_top3` | Карточка позиции с тремя вариантами крупными кнопками; остальное предзаполнено |
| `conf_dish < T_pick`, новое блюдо, или `conf_mass < 0,3` при калорийности позиции > 150 ккал | `ask` | Один короткий вопрос с вариантами («Это блинчики или оладьи?», «Сколько примерно: ½ тарелки / тарелка / больше?») |
| Фото плохое / не еда | `ask` | «Не вижу еды на фото — переснять?» |

**Подбор порогов.** `T_auto` подбирается ежемесячно так, чтобы доля ошибок среди автосохранённых позиций была ≤ 3 % (на последних 4 неделях). Если данных мало — порог остаётся консервативным. Пороги можно задать вручную для каждого участника (например, «всегда спрашивать» для ребёнка).

**Режим обучения** (первые 2–4 недели или пока в каталоге < 30 блюд с ≥ 5 эталонами) — `auto_save` отключён: всё подтверждается, но интерфейс предзаполнен, так что подтверждение — один тап.

### 7.4. Уточняющие вопросы
- Не больше **одного** вопроса за запись (если неясностей несколько — задаётся самый «дорогой» по калориям, остальное решается по умолчанию).
- Варианты ответа — кнопками; можно ответить голосом.
- Ответ сразу применяется к записи и сохраняется как обратная связь.

## 8. Обучение на данных семьи

### 8.1. Что считается обратной связью
Каждый итог записи сравнивается с исходной гипотезой и сохраняется в `recognition_feedback`:

| Тип события | Пример | Что обновляется |
|---|---|---|
| `confirmed` | Принято без изменений (явно или авто, без правки 24 ч) | Эталоны, порции, приоры, веса (положительный пример) |
| `dish_changed` | Котлеты → тефтели | Эталоны (у правильного блюда), веса, матрица путаницы |
| `mass_changed` | 180 → 250 г | Калибровка метода массы, порции |
| `item_added` | Добавлен соус | Привычки/модификаторы; признак «модель пропускает соусы» |
| `item_removed` | Удалена лишняя позиция | Матрица ложных срабатываний |
| `new_dish_created` | — | Новое блюдо, первые эталоны |
| `variant_resolved` | Уточнили вариант по вопросу | Приоры вариантов |

Автосохранённая запись, которую не исправили в течение 24 часов, считается подтверждённой, но с весом 0,7 (пользователь мог не заметить ошибку).

### 8.2. Эталонные фото
- После подтверждения из фото вырезаются фрагменты позиций (по `region`), считаются эмбеддинги, фрагменты добавляются в эталоны соответствующего блюда.
- **Дедупликация:** фрагмент не добавляется, если в эталонах блюда уже есть фрагмент с близостью > 0,97 (почти одинаковые кадры).
- **Ограничение:** до 200 эталонов на блюдо; при превышении удаляется эталон, ближе всего находящийся к другим эталонам (сохраняется разнообразие: разное освещение, посуда, ракурсы).
- **Карантин:** эталоны из автосохранённых, но не подтверждённых явно записей помечаются весом 0,7 и могут быть удалены, если позже обнаружится ошибка.
- **Негативные примеры:** при `dish_changed` фрагмент запоминается как «не-X» для неправильного блюда; при визуальном поиске сходство с такими фрагментами снижает скор X.

### 8.3. Синонимы и словарь речи
- Если пользователь голосом назвал блюдо так, что текстовый поиск не нашёл его, а потом выбрал блюдо вручную — фраза (лемматизированная) предлагается как новый синоним («Запомнить, что „Наполеон" — это „Торт слоёный домашний"?»). Подтверждённые синонимы попадают в подсказки STT.
- Аналогично для мер («пиалка» = 250 мл) и имён («мелкая» = Маша).

### 8.4. Новое блюдо
Когда система встречает блюдо, которого нет в каталоге:
1. Предлагает: «Похоже на новое блюдо. Как назовём?» (подставлено название от модели).
2. Тип: домашнее (рецепт — сейчас или позже) / магазинное (сканировать штрихкод) / в кафе / простой продукт.
3. Если рецепта нет — состав временно берётся по ближайшему аналогу из справочника (модель предлагает аналог: «Плов с курицей → аналог из справочника»), с пометкой «состав приблизительный».
4. Блюдо попадает в список «требуют уточнения» в веб-кабинете.

### 8.5. Типичные порции
Для пары (участник, блюдо) хранится робастная статистика подтверждённых масс: медиана, межквартильный размах → CV. Обновляется на каждом подтверждении (по последним 30 записям). Единица счёта блюда (масса 1 котлеты) уточняется по записям, где были и количество, и точная масса (весы или взвешивание партии).

### 8.6. Калибровка оценок массы
По записям с точной массой (М0/М1 — «контрольные взвешивания») вычисляются поправочные коэффициенты:
- `k_модели(категория) = медиана(истинная / оценка модели)` — например, модель систематически недооценивает гарниры на 15 % → k = 1,15;
- `k_посуды(посуда, категория)` для М3;
- обновлённые σ методов (фактическая дисперсия ошибки).

Приложение **предлагает контрольные взвешивания** адресно: раз в несколько дней для блюд с наибольшей неопределённостью массы и большой долей в калориях («Взвесьте, пожалуйста, порцию плова перед едой — это улучшит точность»). Целевой объём: 2–3 взвешивания в неделю в период обучения, затем по необходимости.

### 8.7. Отчёт качества и предложения (ночная задача)
- **Метрики** за 7/30 дней: top-1, top-3, доля авто, доля исправлений, MAPE массы (по контрольным взвешиваниям), среднее время записи, доля `ask`.
- **Матрица путаницы** блюд → пары, которые путаются > 15 % случаев:
  - если составы близки (разница калорийности < 10 % и БЖУ < 15 %) → предложение **слить** блюда или объединить в группу вариантов;
  - если составы разные → предложение **досъёмки**: «Сфотографируйте тефтели и котлеты рядом» / добавить различающее визуальное описание.
- **Блюда с малым числом эталонов** (< 5) среди частых → подсказка «доснять».
- **Деградация:** если top-1 за неделю упал > 3 п. п. — уведомление администратору с причинами (новые блюда, смена модели, новая посуда).

### 8.8. Регрессионный контроль при изменении моделей
Перед сменой модели/промпта/весов прогоняется **золотой набор** — 300–500 последних подтверждённых записей (фото + правильный ответ). Новая конфигурация принимается, если top-1 и MAPE не хуже текущих (допуск 1 п. п.). Набор пополняется автоматически.

## 10. Обработка особых ситуаций

| Ситуация | Поведение |
|---|---|
| Нет интернета | Фото/аудио сохраняются локально, запись — черновик «ожидает распознавания» с временем; при появлении сети задача отправляется автоматически; пользователь получает уведомление «распознано: …» |
| Внешний AI недоступен | Распознавание только по эмбеддингам и контексту → `pick_from_top3`; голос — локальный STT + текстовый поиск без модели |
| Несколько фото одного приёма за 10 мин | Предложение объединить в один приём (суп + второе сфотографированы отдельно) |
| Повторное фото той же тарелки (добавка) | Если похоже на позицию, уже записанную в последние 30 мин, — вопрос «Добавка?» → увеличение массы, а не новая запись |
| Фото не своей еды (ресторан) | Блюда вне дома: модель может вернуть `new`; предлагается сохранить с привязкой к заведению — если заведение повторяется, его блюда тоже учатся |
| Ребёнок не доел | Режим «до/после» или голосом «Маша съела половину» |
| Запись задним числом | «Вчера ужинали пельменями» — время из речи; приор считается для указанного слота |
| Непищевой объект | Модель возвращает `image_ok: false` → вопрос |
| Перекрытие блюд (гарнир под котлетой) | Модель оценивает видимую часть; приор порции компенсирует; при низкой уверенности массы — вопрос |
| Блюдо из партии закончилось | Если остаток партии < оценки массы — масса ограничивается остатком; партия предлагается к закрытию |

## 11. Партии приготовленного: логика

1. **Создание партии.** «Приготовил борщ» (голосом, кнопкой, или автоматически из плана «готовка»): выбирается рецепт, фактические изменения («без мяса», «картошки больше») — правкой или голосом. Опционально: вес пустой кастрюли (запоминается для посуды) и полной → фактический выход.
2. **Выход без взвешивания:** по рецепту с коэффициентом уварки/ужарки (из справочника для способа приготовления).
3. **Расход:** каждая позиция приёма пищи со ссылкой на партию — событие расхода.
4. **Взвешивание остатка** (опционально): «в кастрюле осталось 1,2 кг» → система сравнивает с расчётным остатком, расхождение распределяет пропорционально между записями из этой партии без контрольных взвешиваний и **учится**: корректирует коэффициенты массы участников («папины тарелки на 10 % больше, чем оценивает модель»).
5. **Закрытие:** при остатке ≈ 0, вручную («доели/выбросили»), или по сроку хранения (вопрос владельцу партии). Выброшенное фиксируется как списание (не съедено).
6. **Партии повышают точность двумя способами:** точный состав конкретного приготовления и сильный контекстный сигнал (вероятность «борща» резко растёт, пока он есть в холодильнике).

# 04. Планирование рациона и контроль соблюдения

[← к оглавлению](README.md)

## 1. Понятия

| Понятие | Описание |
|---|---|
| План недели | План на 7 дней (пн–вс) для всей семьи; статусы: черновик → утверждён → завершён |
| Запланированный приём (`planned_meal`) | День + слот + участник(и) + список блюд с массой порции |
| Готовка (`planned_cooking`) | Когда и что приготовить; одна готовка (кастрюля супа) обслуживает несколько приёмов пищи |
| Общий приём | Семейный ужин: одно блюдо — разные порции участникам |
| Фиксированный элемент | То, что пользователь закрепил вручную (воскресный пирог, обед в школьной столовой) — оптимизатор не меняет |

## 2. Входные данные планировщика

| Группа | Данные |
|---|---|
| Участники | Нормы энергии и нутриентов, цели, аллергии/запреты, нелюбимые блюда, текущие приоритетные проблемы (из рекомендаций) |
| Расписание недели | Для каждого участника и дня: какие слоты дома, какие вне дома (работа, школа — «столовая» с типовым составом), кто ужинает вместе; задаётся шаблоном недели + правки («в среду гости, +4 человека») |
| Каталог | Блюда с составом, категорией, временем готовки, сроком хранения готового, сезонностью, частотой употребления (= предпочтение), «отказы» в прошлых планах |
| Ограничения готовки | Сколько времени на готовку по дням (будни 40 мин, выходные 2 ч); сколько готовок в неделю максимум |
| Запасы (опционально) | Что уже есть дома (в т. ч. открытые партии) |
| Пожелания | Свободный текст: «на этой неделе без рыбы, хочется больше супов» — LLM переводит в структурированные ограничения |

## 3. Алгоритм составления плана

### 3.1. Постановка задачи
Подобрать для каждого (день, слот, участник или группа участников) блюда и порции так, чтобы:

**Жёсткие ограничения:**
- аллергены/запреты не нарушаются;
- энергия каждого участника за день — в пределах ±10 % от нормы (учитывая перекусы и приёмы вне дома по их типовому составу);
- белок ≥ нижней границы нормы;
- время готовки в день ≤ доступного;
- блюдо готовки потребляется в течение срока хранения (суп — до 3 дней);
- объём готовки = Σ запланированных порций из неё (+ 5 % запас);
- фиксированные элементы сохраняются;
- одно и то же основное блюдо — не чаще N раз в неделю (по умолчанию 3, если это не «остатки» одной готовки).

**Целевая функция (минимизировать):**
```
  Σ_участник Σ_нутриент вес_n × отклонение_за_неделю(n)      — баланс (нормы, приоритетные проблемы с повышенным весом)
+ λ1 × Σ (1 − предпочтение(блюдо, участник))                  — любимые и привычные блюда
+ λ2 × число новых блюд сверх лимита (по умолчанию 2 в неделю)— новизна в меру
+ λ3 × повторы подряд одного блюда                             — разнообразие
+ λ4 × число готовок                                           — меньше возни на кухне
+ λ5 × стоимость (если включён учёт бюджета)
```
Предпочтение блюда для участника = нормированная частота за 8 недель с учётом отказов (блюдо, которое ставили в план, а его заменяли — получает штраф).

### 3.2. Решение
1. **Скелет недели** (CP-SAT, OR-Tools): переменные — выбор блюда для каждого слота из кандидатов (каталог, отфильтрованный по категории слота: завтрак — каши, яйца, творог…; обед — суп + второе; ужин — второе + гарнир/салат) и решения о готовках. Порции на этом шаге — типичные для участника.
2. **Подбор порций** (линейное программирование): при фиксированных блюдах подбираются массы порций каждому участнику в пределах [0,7; 1,3] × типичная порция, чтобы минимизировать отклонения по нутриентам.
3. **Лимит времени решения** — 20 с; если оптимальное решение не найдено — лучшее найденное. Если ограничения несовместимы (например, норма недостижима из-за запретов) — план строится с ослаблением ограничений, и пользователю объясняется, какое ограничение ослаблено.
4. **Пояснение плана:** LLM получает итог (что поменялось относительно привычного рациона и почему) и пишет 3–5 строк: «На этой неделе 2 раза рыба вместо курицы — для витамина D и омега-3; суп в понедельник — на два дня».

### 3.3. Редактирование
- Перетаскивание блюд между днями; замена блюда — система предлагает 5 альтернатив, ранжированных по тому, насколько они сохраняют баланс недели (пересчёт целевой функции при замене) и по предпочтению.
- Закрепление элементов и повторная оптимизация остального («Пересобрать остальное»).
- Сохранение удачной недели как шаблона.
- Одновременная правка: мягкая блокировка недели (см. [01-server.md](01-server.md), п. 5.3).

## 4. Список покупок
1. Из всех готовок плана суммируются ингредиенты рецептов (масса брутто) + простые продукты и магазинные позиции из приёмов пищи.
2. Вычитаются запасы (если ведутся) и остатки открытых партий.
3. Переводятся в покупаемые единицы: масса → упаковки (по типичной упаковке продукта, которую семья покупает — запоминается из штрихкодов/чеков), штуки (яйца — десятками).
4. Группировка по отделам магазина; отметки «куплено» синхронизируются между устройствами в реальном времени (один покупает, другой видит).
5. Экспорт текстом (для мессенджера).

## 5. Контроль соблюдения плана

### 5.1. Сопоставление факта и плана
При каждом сохранении приёма пищи система ищет соответствующий запланированный приём:
1. Кандидаты — запланированные приёмы того же участника в тот же день, слот которых совпадает или соседний (окно ±2 ч от типичного времени слота).
2. Для каждого кандидата — сопоставление позиций (паросочетание по максимальному сходству):
   - то же блюдо → совпадение 1,0;
   - вариант из той же группы → 0,8;
   - та же категория и близкий состав (разница энергии на 100 г < 20 %) → 0,5 (эквивалентная замена);
   - иначе 0.
3. Выбирается кандидат с максимальной суммой сходства; если сумма < 0,3 — факт считается «вне плана».

### 5.2. Статусы

| Статус приёма | Условие |
|---|---|
| Выполнен по плану | Все основные позиции совпали (≥ 0,8), масса в пределах ±25 % |
| Выполнен с заменой | Есть эквивалентные замены (0,5) или отклонение массы 25–50 % |
| Заменён | Записан приём в этом слоте, но совпадение < 0,3 |
| Пропущен | Слот прошёл (+ 3 ч), записей нет; уточняется вопросом «Пропустили или забыли записать?» — чтобы отличить отсутствие приёма от отсутствия записи |
| Вне плана | Записанный приём без соответствия (незапланированный перекус) |

### 5.3. Метрики соблюдения
- % приёмов «по плану» + «с заменой» — по участнику, по слотам, по дням недели.
- Отклонение энергии и БЖУ факта от плана (за день и неделю).
- Энергия «вне плана» (перекусы).
- Готовки: состоялись ли (создана ли партия запланированного блюда).

### 5.4. Реакция на отклонения
- **В течение дня:** если к вечеру энергия сильно отличается от плана (например, плотный незапланированный обед) — подсказка к ужину: «Ужин можно сделать легче: порция 250 → 180 г» (масса пересчитывается подбором порций, п. 3.2, шаг 2, для оставшихся слотов дня).
- **При пропущенной готовке:** предложение сдвинуть блюда, зависящие от неё, и пересобрать оставшиеся дни.
- **Еженедельный разбор (воскресенье):** что соблюдалось хуже всего и типичные причины (по комментариям и паттернам: «будний обед систематически заменяется — обедаете вне дома?»); предложения для следующего плана: изменить шаблон недели, убрать блюда, которые трижды подряд заменяли, упростить будние готовки. Принятые изменения применяются к следующему черновику автоматически.

## 6. Напоминания, связанные с планом

| Напоминание | Когда | Кому |
|---|---|---|
| Что готовить сегодня | Утром или за N часов до готовки (время готовки — из расписания) | Ответственному за готовку |
| Разморозить мясо | Накануне вечером, если рецепт требует | Ответственному |
| Приём пищи | В типичное время слота, если записи нет (с отсрочкой 1 ч и «тихими часами») | Участнику |
| Партия заканчивается / истекает срок | По событию | Всем взрослым |
| Черновик плана готов | Суббота | Администратору / ответственному за план |
